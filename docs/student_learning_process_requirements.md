# 学生学习全过程智能体需求文档草案

- 版本：v0.1
- 日期：2026-07-08
- 适用项目：智启校园智能体
- 目标板块：学生学习全过程
- 学校场景：南京审计大学，突出审计学习、智能审计、审计案例实训

## 1. 背景与定位

本模块面向大学生从课前、课中、课后到考试/实训/竞赛的完整学习过程，提供资料翻译、课程知识库、源文引用问答、思维导图、练习测评、学习路径与审计案例实训能力。

南京审计大学是我国唯一一所以“审计”命名的全日制普通高校，学校定位和资源天然适合把通用学习助手做成“审计学习智能体”。因此本模块不只做普通 RAG 问答，还需要形成审计特色：审计准则与法规学习、政府审计/内部审计/社会审计对比、审计流程训练、审计证据链、工作底稿、审计报告与智能审计数据分析入门。

## 3. 从 Awesome-LLM-Apps 可参考的模块

1. AI Teaching Agent Team：把教学能力拆成教授、学习路径顾问、资源馆员、助教四类角色。可迁移为学生侧的“知识讲解、路径规划、资源推荐、练习批改”。
2. Multimodal Agentic RAG：支持文本、URL、PDF、图片、音频、视频等资料摄取，回答时展示引用。首版建议先支持 PDF/DOCX/TXT/MD，后续扩展 PPTX、图片 OCR、视频字幕。
3. Knowledge Graph RAG with Citations：从文档抽实体与关系，支持多跳推理和来源追踪。适合审计案例中“主体、资金流、交易、风险点、证据、结论”的关系建模。
4. Generative UI 与 UI/UX Feedback：适合后续把回答变成可编辑的学习计划、思维导图、审计流程图、错题卡片，而不是只输出纯文本。

## 4. 目标用户与核心场景

| 用户 | 需求 |
| --- | --- |
| 本科生/研究生 | 快速理解课件、教材、论文和案例；生成复习计划、思维导图、练习题；完成审计实训 |
| 审计相关课程学生 | 学审计准则、审计流程、审计证据、风险评估、工作底稿和报告写作 |

## 5. 核心用户流程

### 5.1 一键翻译学习资料

学生上传英文教材、审计准则、论文或案例 PDF/DOCX，系统识别段落与术语，生成中文译文，可导出中文文档。理想状态下支持中英对照、术语表、翻译质量检查。

### 5.2 课程资料知识库

学生上传课件、课本、教师讲义、案例材料，系统自动解析、分块、索引，形成某门课程的知识库。学生提问时，回答必须引用来源片段，避免无依据编造。

### 5.3 思维导图与学习产物生成

系统可基于某个章节或整门课程生成知识结构图、复习清单、闪卡、练习题、模拟卷、错题本和阶段学习报告。

### 5.4 审计案例实训

学生上传审计案例、财务资料、制度文件或 CSV/XLS 数据，系统辅助识别风险点、审计目标、审计程序、证据清单、工作底稿和报告要点。

## 6. 功能需求

### F1 文档一键翻译

- 支持上传 PDF、DOCX；二期支持 PPTX、XLSX、图片 OCR。
- 支持选择目标语言，默认英文到中文。
- 支持审计术语表，例如 audit evidence、materiality、internal control、substantive procedure 等。
- 支持导出中文 DOCX/Markdown；二期支持保留版式 PDF。
- 显示翻译进度、失败段落、重试入口。
- 对长文档按章节/页码分段处理，避免一次性请求过长。

### F2 网页端实时翻译/网页资料导入

- 支持粘贴 URL 或网页正文，生成双语阅读视图。
- 支持一键加入课程知识库。
- 对网页资料保留来源 URL、标题、抓取时间。
- 后续可做浏览器扩展，实现当前网页划词、段落翻译和整页翻译。

### F3 课程知识库创建

- 支持按“课程/章节/资料类型/教师/学期”管理资料。
- 当前项目已支持 TXT、MD、PDF、DOCX 上传和基础检索，应继续保留。
- 增强为向量检索 + 关键词检索 + 重排，回答必须带引用。
- 支持删除、重新索引、资料版本更新。
- 支持扫描版 PDF/OCR 作为二期能力。

### F4 学习问答与讲解

- 支持概念解释、例题讲解、课件总结、论文摘要、章节复习。
- 回答结构建议固定为：结论、依据、展开解释、例子、易错点、参考来源。
- 若知识库没有依据，必须明确提示“资料中未找到直接依据”。

### F5 思维导图/知识图谱

- 支持从课程资料生成 3 层以上结构：课程 -> 章节 -> 知识点 -> 例题/案例。
- 首版可导出 Mermaid/Markdown/HTML；二期支持可交互图谱、XMind、PNG/SVG。
- 审计场景下支持生成“风险-控制-程序-证据-结论”关系图。

### F6 测验与复盘

- 支持生成选择题、判断题、简答题、案例分析题。
- 每题包含答案、解析、难度、知识点标签。
- 支持错题记录、薄弱点诊断、下一轮复习计划。
- 支持导出学习报告，用于竞赛演示和学生自查。

### F7 南审审计学习特色功能

- 审计基础学习助手：围绕审计本质、审计目标、审计程序、审计证据、重要性、审计风险模型、审计报告等内容讲解。
- 三类审计对比：政府审计、内部审计、社会审计的目标、主体、依据、流程、报告、案例对比。
- 审计准则与法规助手：支持审计法、国家审计准则、注册会计师审计准则、内部审计准则等资料问答。
- 审计流程模拟器：从业务承接/审计立项、计划、风险评估、控制测试、实质性程序、审计证据、工作底稿、报告形成完整训练。
- 审计案例库：支持经济责任审计、财政审计、金融审计、资源环境审计、工程审计、内部控制审计、智能审计案例。
- 工作底稿生成：根据案例生成审计目标、审计程序、所需证据、执行记录、发现问题、结论建议。
- 审计证据链：把问题线索、证据来源、判断标准、审计结论连接起来，降低“只给结论无依据”的风险。
- 智能审计数据分析入门：支持上传 CSV/XLS，做重复报销、异常金额、日期异常、供应商集中度、Benford 分析等演示级检查。

### F8 学习全过程管理

- 学习目标设置：考试、论文阅读、课程预习、实训、竞赛。
- 学习路径生成：按周/日拆解任务。
- 进度看板：资料数、已学章节、练习完成率、薄弱知识点。
- 阶段报告：本周完成内容、待复习内容、建议下一步。

### F9 账号与权限

- 当前项目已有南京审计大学信息门户的虚拟登录入口。
- 后续真实版本可接入学校统一身份认证。
- 资料权限至少区分个人资料、课程共享资料、公开资料。
- 学生上传资料默认仅本人可见，课程资料由教师或管理员授权共享。

## 7. MVP 范围建议

### 第一阶段：可演示闭环

目标是在当前 `smart-campus-agent` 基础上尽快形成“上传资料 -> 建知识库 -> 审计学习问答 -> 生成思维导图/测验/报告”的闭环。

- 新增“审计学习助手”或把学习助手细化为“通用学习/审计学习”。
- 内置少量审计示例资料：审计学基础、审计流程、审计准则摘要、案例片段。
- 保留当前 PDF/DOCX/TXT/MD 上传能力。
- 新增思维导图生成，首版用 Mermaid 或 Markdown 树。
- 新增测验生成：选择题、简答题、案例分析题。
- 新增 DOCX/PDF 文档翻译原型，先导出 Markdown 或 DOCX，不强求 PDF 原版式。
- UI 上增加课程资料区、学习产物区、审计案例实训区。

### 第二阶段：增强体验

- 接入向量数据库，例如 Chroma、FAISS、Milvus 或 pgvector。
- 支持 PPTX、图片 OCR、扫描 PDF。
- 支持术语表和翻译记忆。
- 支持可交互思维导图和知识图谱。
- 支持中英对照阅读和段落级重新翻译。

### 第三阶段：校内集成

- 接入南京审计大学统一身份认证。
- 对接课程平台、信息门户或教师上传入口。
- 做课程级共享知识库。
- 做审计案例库与数据审计实验库。
- 如确有必要，再做浏览器扩展或网页划词插件。

## 8. 技术方案建议

### 8.1 总体架构

- 前端：当前原生 HTML/CSS/JS 可继续演示；若后续交互复杂，可迁移 React/Vite。
- 后端：继续使用 FastAPI。
- 存储：当前 SQLite 可支撑 demo；向量检索建议二期加入 Chroma/FAISS/pgvector。
- 模型接口：保留 OpenAI 兼容接口，便于接千问、GLM、DeepSeek、本地 Ollama 等。

### 8.2 知识库流程

上传文件 -> 文本抽取/OCR -> 清洗 -> 按章节/页码分块 -> 嵌入向量 -> 检索重排 -> 带引用回答 -> 生成学习产物。

### 8.3 翻译流程

上传文件 -> 解析段落/表格 -> 应用审计术语表 -> 分段翻译 -> 质量检查 -> 合并导出 -> 支持人工重译某段。

### 8.4 思维导图流程

资料检索/章节摘要 -> 抽取层级 JSON -> 渲染 Mermaid/Markmap/React Flow -> 导出 PNG/SVG/Markdown。

### 8.5 审计案例流程

案例资料 -> 抽取主体、事项、金额、时间、制度依据 -> 识别风险点 -> 生成审计程序 -> 关联证据 -> 生成工作底稿与报告摘要。

## 9. 数据与资料准备

首版建议准备以下资料进入知识库：

- 南京审计大学学校简介、国家审计学院专业介绍。
- 审计学基础课程说明、审计学通论或相关公开课资料。
- 审计法、国家审计准则、注册会计师审计准则、内部审计准则的公开资料或摘要。
- 审计流程示例：审计计划、风险评估、审计证据、审计报告。
- 2-3 个脱敏审计案例：财政资金、内部控制、固定资产投资或采购报销。
- 1-2 份演示用 CSV/XLS 数据：报销明细、供应商付款、固定资产台账。

资料使用必须注意版权和隐私。教师课件、教材扫描件、案例材料如果用于公开演示，需要确认授权或使用脱敏/自造样例。

## 10. 验收标准

- 上传一份审计相关 PDF/DOCX 后，系统能完成解析、索引，并在问答中展示来源片段。
- 输入“解释审计风险模型并举例”，系统能给出结构化答案，并提示资料依据。
- 输入“根据这份课件生成思维导图”，系统能输出至少 3 层结构。
- 输入“生成 10 道审计学基础练习题”，系统能给出题目、答案、解析、知识点。
- 上传一份英文审计材料，系统能生成中文译文并导出。
- 输入一个审计案例，系统能生成审计目标、风险点、审计程序、证据清单和工作底稿框架。
- 页面上能清晰区分资料上传、问答、学习产物、审计实训，不让用户只面对一个聊天框。

## 11. 主要风险

- PDF/扫描件解析质量不稳定，可能影响知识库和翻译质量。
- 版权材料不能随意用于公开演示。
- 审计法规和校内通知存在时效性，必须标注来源与更新时间。
- 审计案例涉及敏感数据，必须脱敏。
- 模型可能编造审计结论，必须强制引用来源并提示置信边界。
- 浏览器扩展开发成本高，建议先做网页文本/URL 导入。

## 12. 待确认问题

1. 首版演示优先级：一键翻译、知识库问答、思维导图、审计实训，哪个必须作为主亮点？
2. 演示资料能否使用真实课程课件？如果不能，需要尽快准备脱敏样例。
3. 是否必须支持 PPTX？若竞赛演示以课件为主，PPTX 优先级应提高。
4. 是否需要真实模型 API？当前项目有 mock 模式，但正式演示建议接真实 OpenAI 兼容模型接口。
5. 是否要把“审计学习”做成独立入口，还是放在“学习助手”里的专业模式？
