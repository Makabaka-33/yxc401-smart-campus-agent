# 学生事务助手 MVP（第一版）

## 版本范围

- 学校：南京审计大学（江苏南京）
- 用户身份：学生
- 学段：本科生、研究生
- 使用场景：比赛 / 答辩演示
- 页面原则：两个学段使用同一布局，事务卡片、重点提醒、服务说明和消息内容按档案切换

本分支访问根网址后默认进入“事务助手”，并保留图 1 式左侧导航。右上角可在“张同学 · 本科生”和“李同学 · 研究生”两套模拟档案之间切换；学习助手、教学助手和原智能体首页仍可从侧栏进入。

## 页面模块

1. **我的事务**：展示状态、材料完成度、下一步、负责部门、截止时间和详情按钮；材料勾选保存在浏览器本地。
2. **近期重点**：根据学段推送报名、培养、奖助和证明服务，可加入本地待办。
3. **校园服务**：提供教务处、研究生院、图书馆、校园导航、校园卡、证明打印、宿舍和学校主页入口。
4. **校园消息速览**：从教务处、研究生院、学生工作处和图书馆官网聚合具体通知文章；先按本科生/研究生身份过滤，再按发布日期倒序展示。卡片直达文章页，并显示来源、发布日期、匹配原因和截止状态。
5. **事务 Agent**：先检索当前档案的结构化事务；未命中时调用现有 `/api/chat`，并把学段、年级和学院作为身份上下文传入。

## 数据状态

页面对信息可信度作显式区分：

- **官方已核验**：来自南京审计大学公开网站，可跳转查看原始页面。
- **演示模拟**：为答辩闭环制作的档案、办理进度或未来日期，不代表学校真实业务状态。
- **待学校确认**：公开网页没有完整披露流程，需要通过校内系统、学院或办理部门确认。

本地演示状态存储在浏览器 `localStorage`，不会写入学校业务系统，也不代表真实审批结果。

## 结构化事务字段

每条事务使用统一字段：

```text
事项名称、负责部门、适用对象、当前状态、下一步、截止时间、
所需材料/步骤、信息状态、来源标题、来源网址
```

后续采集完整流程时再补充申请条件、办理时间、线下地点、联系电话和常见问题。

- 新增 `frontend/affairs-data.js`，集中管理两套学生演示档案和官方来源。

- 新增 `/api/affairs/notices` 资讯聚合接口：实时抓取学校各部门官网、按身份过滤、按时间排序，并在官网超时或结构变化时返回已核验的文章级回退数据。

## 当前限制与下一步

- 学生证补办、宿舍报修、场馆预约、研究生成绩证明等公开信息不完整，当前明确标记为“待学校确认”。
- 第一版没有接入学校统一身份认证、真实审批流、消息推送或真实个人数据。
- 官网聚合依赖公开网页结构和本地网络；接口设置了短时缓存与文章级回退数据，页面支持手动刷新。
- 下一步可补充经过脱敏的校内流程截图和材料清单，再将结构化数据迁移到后端知识库。
